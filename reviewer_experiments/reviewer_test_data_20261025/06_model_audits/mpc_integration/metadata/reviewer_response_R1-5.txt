Reviewer 1, Comment 5

Comment:
One potentially interesting application of the proposed framework would be its integration with MPC. Are there any particular considerations or limitations that should be taken into account when using the resulting model for prediction and control? For instance, how might the delays affect prediction accuracy, closed-loop stability, or computational requirements?

Response:
Thank you for this suggestion. We have added a discussion of how the predictor could enter an MPC formulation, distinguishing its existing causal prediction path from the objective, constraints, solver, feedback update, and stability analysis needed for a controller. The additions are in Section 4.4, with an interface audit in Appendix B.

At decision time k, initialization uses observed states through x_k and applied inputs through u_{k-1}. The future sequence U_k = (u_{k|k}, ..., u_{k+H_p-1|k}) consists of optimization variables and enters the forecast through B; no future state measurements are required. In the released interface, current_action denotes the first candidate u_{k|k}, so it must change with each candidate sequence rather than remain fixed to u_{k-1}. A controller would impose actuator and predicted-state constraints with consistent physical units and training normalization, optimize tracking and control-move penalties, apply the first move, and repeat with updated measurements. Re-encoding the new causal history and restarting the forecast context follows the present prediction protocol; these operations must also enter the closed-loop analysis.

Although A and B are fixed during prediction, the AFT correction depends nonlinearly on latent states generated under the candidate inputs. Consequently, the full MPC problem is generally nonlinear even with quadratic tracking penalties and linear physical constraints. The convex quadratic-program structure of fixed linear lifted predictors (Korda and Mezic, 2018) therefore cannot be assumed for DLM-K. The tensor recurrence permits differentiation with respect to candidate inputs with frozen model weights. Its no-gradient, array-returning evaluation wrapper would need to be replaced by a differentiable optimization interface. The initial lift can be cached during a control update; the input-dependent memory corrections must still be recomputed for each candidate.

We checked this interface on the original frozen CSTR checkpoint using an existing 20-state history and eight candidate input moves. An in-memory float64 copy was used for the derivative check only. The Jacobian blocks for future inputs relative to earlier predicted states were exactly zero. An automatic directional derivative of a scalar output functional agreed with a central finite difference to a scaled error of 5.62e-10. Caching the fixed lift gave identical predictions and input gradients. These are prediction-interface checks, not an optimization or closed-loop control experiment; no weights or plant trajectories were updated.

The CSTR delay is a recycle-state delay. An additional actuator delay would require a queue of issued commands, with only uncommitted inputs available for optimization; sensor delay would require causal state estimation. The physical prediction horizon must capture relevant delayed responses and the control objective. A horizon exceeding the delay, or a longer history or latent buffer, is not an accuracy guarantee. Longer rollouts accumulate model error, and optimized inputs can leave the identification excitation regime. Control-oriented tests would therefore need to assess changed input profiles, constraints, and disturbances. Unknown future process-noise realizations must not be supplied as if they were known control inputs. Our delay and noise results remain open-loop prediction evidence.

Low prediction RMSE and a regularized linear-core spectral radius do not establish recursive feasibility or stability of the controlled delayed plant. One conditional MPC design route uses an admissible target, a suitable stage cost, and terminal invariance and decrease conditions under an admissible local control law, with explicit robustness treatment of model and estimation errors (Rawlings et al., 2024). For this predictor, such conditions would need to be established for an appropriate delay/history-augmented description including the feedback reinitialization. Empirical trajectory errors do not supply uniform constraint-tightening bounds. We have not constructed or validated these controller ingredients.

Computational cost includes repeated input-dependent rollouts, derivatives, constraint assembly, and solver iterations at each update. With all moves free, single shooting has H_p n_u input variables. Each candidate retains the recurrent complexity stated in Appendix B; increasing the horizon, reducing the sampling interval at fixed physical duration, or enlarging latent memory increases work and storage. Cached initialization, move blocking, warm starts, and final-query AFT evaluation are possible implementation choices requiring controller-level checks. The existing batch prediction and training memory measurements are not MPC latency measurements. Solver convergence, closed-loop constraint satisfaction and tracking under delay/noise, and worst-case update time on the intended hardware would need separate validation.
